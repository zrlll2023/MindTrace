# MindTrace 设计文档（Spec）

- 日期：2026-09-14
- 状态：待用户审阅
- 流程：brainstorming（架构级）产物；批准后进入 writing-plans 写实施计划
- 约定：面向用户的一切内容（界面、报告、文档）均为中文

---

## 1. 一句话定位

一个**本地优先**的桌面应用：把你的生活倒进一个聊天框，AI 分析师把它变成日报/周报、你自己看不见的规律、以及为你定制的成长内容——**原始数据永远不出你的电脑**。

## 2. 目标与成功标准

### 2.1 要解决的问题

- 睡眠、琐事、对话、喜欢的句子/内容散落在各处（微信收藏、浏览器书签、聊天记录、脑子），无法回顾和分析
- 手动记日记摩擦太大，坚持不了两周
- 收藏了很多内容，但从来没有 AI 帮你把"你关心的东西"串成线并持续推进

### 2.2 成功标准（MVP 验收）

1. **录入摩擦 < 30 秒**：一次随手 dump（混合睡眠+事件+想法）在 30 秒内完成录入与确认归档
2. **日报有价值**：连续使用 7 天后，日报里至少出现一条"自己没意识到的规律"或"一条推进兴趣线的推荐"，而不是复述当天录入
3. **数据主权**：卸载应用后，数据目录仍是可读的 SQLite + Markdown 文件，无服务器依赖
4. **可换模型**：设置页换一个 LLM 提供商（DeepSeek ↔ GLM ↔ Ollama）不需要改任何代码

### 2.3 非目标（YAGNI，明确不做）

- 不做移动端（v1）
- 不做云同步、账号体系、多用户
- 不做浏览器自动化操控（记为远期实验，见 §11）
- 不做日历/待办管理（MindTrace 只记录与分析，不做 GTD）

## 3. 总体架构

**技术栈：Tauri 2 + Vue 3 + TypeScript + SQLite（经 Tauri 的 Rust 侧访问）**

```
┌─────────────────────────────────────────────┐
│  Vue 3 前端（Tauri WebView）                 │
│  ├─ 捕获页（聊天框，首页）                    │
│  ├─ 时间线页（浏览/筛选/搜索所有记录）         │
│  ├─ 报告页（日报/周报 Tab + 归档 + MD导出）    │
│  └─ 设置页（提供商适配器 / 隐私开关 / 数据目录）│
└──────────────┬──────────────────────────────┘
               │ Tauri Commands (IPC)
┌──────────────▼──────────────────────────────┐
│  Rust 后端                                   │
│  ├─ SQLite 存储 + FTS5 全文检索              │
│  ├─ 调度器（每日定时报告任务）                 │
│  ├─ 分析引擎（流水线 + 有界 Agent 步骤）       │
│  ├─ 适配器层：LLM 适配器 / 搜索适配器 /        │
│  │            导入器（v2）                   │
│  └─ Markdown 导出器                          │
└─────────────────────────────────────────────┘
         │ 仅分析文本出网（可脱敏）
         ▼
   OpenAI 兼容 API（DeepSeek 等） + 搜索 API（v2）
```

**目录约定（数据目录，用户可在设置中指定，默认 `%APPDATA%/MindTrace/`）：**

- `mindtrace.db` — SQLite 主库
- `exports/` — 导出的日报/周报 Markdown
- `backups/` — 每日自动备份（保留最近 30 份）

## 4. 数据模型

### 4.1 核心表

**entries（原始与结构化记录，一石二鸟设计）**

| 字段 | 说明 |
|------|------|
| id, created_at | 主键、时间 |
| raw_text | 用户原始输入（永不修改，审计依据） |
| kind | 记录类型：`sleep / event / conversation / quote / idea / media / other` |
| content | AI 结构化后的正文（JSON，按 kind 有不同 schema） |
| confidence | AI 解析置信度（低置信度在前端标黄提醒确认） |
| source | 来源：`chat / import / clipboard / voice`（v2 起扩展） |
| embedding | 向量（v2 加语义检索时启用，NULL 允许） |

**threads（兴趣线）**

| 字段 | 说明 |
|------|------|
| id, title | 如"RAG 评估方法" |
| description | AI 维护的一句描述 |
| status | `active / dormant / closed`（连续 14 天无关联自动 dormant） |
| strength | 强度分（近期关联次数衰减加权） |

**entry_threads（多对多关联）** — 哪条记录属于哪条线，由 AI 分析时写入，用户可手动改。

**reports**

| 字段 | 说明 |
|------|------|
| id, type, period | 类型 `daily / weekly`，覆盖时间段 |
| content_md | 报告正文（Markdown） |
| meta | JSON：消耗 token 数、使用的模型、生成的洞察条数、引用的 entry id 列表 |

**settings（键值对）** — 提供商配置、API Key（本机加密存储）、隐私开关、数据目录、调度时间。

### 4.2 结构化 content 的 schema 示例

- `sleep`：`{ "hours": 6.5, "quality": "poor|ok|good", "note": "..." }`
- `quote`：`{ "text": "...", "author": "...", "why": "AI 推测的收藏理由，可改" }`
- `event`：`{ "summary": "...", "people": [...], "emotion": "frustrated", "tags": [...] }`
- `idea`：`{ "text": "...", "topic_guess": "RAG评估" }`

## 5. 捕获流程（生死线）

1. 用户在首页聊天框输入一段混合 dump（支持语音输入按钮，v1 可后置）
2. AI 解析（一次调用，输出多个结构化条目 + 置信度）
3. **确认 UI**：以卡片形式展示 AI 归档结果，如 `😴 6.5h ✓ │ 😞 事件 ✓ │ 📖 句子 ✓ │ 💡 想法: RAG ✓`，点卡片可改类型/内容/删除
4. 确认后写入 SQLite；`raw_text` 原样保存

**摩擦预算**：从打开应用到确认完成 ≤ 30 秒；聊天框有全局快捷键（如 `Alt+Space`）随时唤起。低置信度条目才需要用户注意，其余一键确认。

## 6. 分析引擎（已确认：A + 有界 B）

### 6.1 固定流水线（A）

```
读取当日 entries → 关联历史（见 6.2）→ 更新 threads → 生成报告 → 写库/导出
```

### 6.2 有界 Agent 步骤（B 的边界）

报告生成前，AI 可**有限次**（上限 6 次工具调用）调用以下本地工具：

- `query_entries(filter, keyword, date_range)` — 查自己的历史
- `get_thread(thread_id)` — 取某条兴趣线的全部关联记录
- `correlate(metric_a, metric_b, date_range)` — 简单相关分析（如睡眠 vs 当日标签）

超限即强制进入撰写阶段。**v1 不给联网搜索工具**（搜索是 v2 的搜索适配器）；这个有界循环的成本上限 = 约 6 次额外调用，可预估。

### 6.3 报告结构（日报示例骨架）

1. **今日存档**：按类型归档当天录入（简洁，不复述原文）
2. **看不见的规律**（0–2 条）：跨天对比、相关性（例："近 3 次睡眠 < 7h 的次日，你记录的负面事件明显增多"）
3. **兴趣线推进**（1–3 条）：活跃 thread 的进展 + "你还没回答的问题"（v2：+一条搜索来的推进内容）
4. **明日关注**（1 条）：基于 thread 与未完成想法的建议
5. **元信息**：token 消耗、生成时间

周报在日报基础上加入：周趋势图数据（睡眠曲线、各类型条数）、thread 周报、上周报告承诺的回顾。

## 7. 设置页与提供商适配器（用户明确的需求）

- 点击提供商预设（DeepSeek / 智谱 / Moonshot / SiliconFlow / Ollama / 自定义）→ 自动填 base URL
- 通过 `{base_url}/models` 自动拉取可用模型列表 → 下拉选择
- 文本框输入 API Key（本机加密存储，界面打码显示）
- 「测试连接」按钮验证可用性
- 搜索适配器（v2）同页配置：Tavily / 博查 / 手动模式（AI 整理搜索建议给用户，用户搜完贴回）

## 8. 隐私设计

- 全部数据本地 SQLite；无账号、无服务器
- 出网内容**仅限**：解析调用（当日 dump 文本）与报告调用（检索到的相关记录文本）
- 「脱敏发送」开关：发送前用本地规则替换人名等标识符（v1 提供基础版：正则 + 用户维护的替换表）
- API Key 用 OS 密钥链/DPAPI 加密存储，不明文落盘

## 9. 阶段划分

| 阶段 | 内容 |
|------|------|
| **MVP** | 聊天捕获 + AI 解析 + 确认 UI + 时间线 + 日报（定时+手动）+ 周报（复用日报流水线）+ 报告页/MD 导出 + 提供商适配器 + 有界 Agent 查询自己的历史 |
| **v2** | AI 对话记录导入（官方数据导出 ZIP 解析：ChatGPT/Claude 等）+ 搜索适配器 + thread 联网推进 + 语音输入 + 剪贴板监听 |
| **v3** | 周报引导式研究工作台、相关性面板、浏览器自动化实验（插件接口隔离） |

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| 录入坚持不下来（最大风险） | 摩擦预算硬指标 + 全局快捷键 + 确认 UI 防止"归档了但不对"的失控感 |
| LLM 解析不稳定 | raw_text 永久保留；低置信度标黄；用户修正作为后续 few-shot 示例 |
| 报告空洞/复述感 | 成功标准 2 强制"规律或推进"；有界 Agent 必须引用具体历史 entry 才算洞察 |
| token 成本失控 | 日报固定预算（约 3–6k tokens/天）；报告调用前显示预估成本；设置页可查历史消耗 |
| Tauri/Rust 学习成本 | Rust 侧保持薄：存储 + 调度 + HTTP；复杂逻辑放 SQL 与前端 TS |

## 11. 已定默认值（可否决）

以下三点在 brainstorming 中已倾向明确，写入 spec 作为默认决策；你可以在审阅时否决任何一条：

1. **日报触发方式**：当日首次打开应用时生成（若无当日报告则自动生成），不依赖后台常驻进程；设置页可手动触发任意日期的报告
2. **语音输入**：v1 不做（聊天框打字已满足摩擦预算；语音留到 v2 与 ASR 一起评估）
3. **嵌入向量/语义检索**：放 v2（v1 用 SQLite FTS5 关键词检索已够用；缩小 MVP 体积）
